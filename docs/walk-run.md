# 走跑二分类候选与当前交付的关系

核对日期：2026-10-24。当前推理库 1.0.1 和服务 1.1.1 没有接入独立走跑二分类，四类输出中的 `walking_running` 合并行进相关活动。按需可以另行提供研究候选模型及评估资料；提供候选不等于已经完成目标设备验收。

## 已有候选

PE1 于 2026-10-19 完成：公开开发选出的 `xgb70` 走跑分支有 3 个 XGBoost 成员，使用 70 维加速度特征，判跑阈值为 0.80。它在父模型判为行进的范围内给出子类；父模型漏掉行进时，子模型不能补救。阈值不代表校准后的正确概率。

研究主要使用公共 IMU 来源。胸前基线包括 PAMAP2、MHEALTH，扩充对照涉及 HARTH、WISDM 2010、WISDM 2019 手机、REALDISP、SAD 等；来源的佩戴位置、标签支持和人员角色分别评估。上述名称描述研究范围，不表示每个来源都被最终候选采纳。公开开发先按人交叉验证，再冻结候选和阈值，最后评价保留人员和历史公司设备记录。

## 为什么目前没有接入

| 证据 | 结果与含义 |
|---|---|
| 公共逐来源测试 | 总研究门槛 FAIL。REALDISP 跑步召回率 64.98%，WISDM 2010 为 69.68%；并非全部来源已达标 |
| 高分但支持少的来源 | MHEALTH 跑步精确率、召回率均为 100%，但只有 1 位跑步测试人员，结论仍为 INCONCLUSIVE |
| 公司设备跑步 | 2 人、2 个事件、31.6 秒；识别 0/2。两段被父模型识别为行进，子模型判为非跑步 |
| 当前交付 | 沿用四类标签；没有在 wheel 或 HTTP 接口启用该候选 |

因此准确表述是“**缺少足够且有代表性的公司设备跑步数据，且现有少量验证未通过**”，不能写成完全没有真实跑步数据，也不能把公共条件子分类分数当作公司设备端到端五分类成绩。现有证据不支持直接作为已验证的产品功能使用。

需要接入时，先明确区分步行、慢跑、跑步、楼梯和短动作的目标定义，补充规范胸前佩戴的目标设备数据及可靠标注，冻结验收口径，再验证召回率、误报、逐人稳定性和端到端结果。候选交付与功能接入应形成单独版本，不原地改变当前四类模型。
